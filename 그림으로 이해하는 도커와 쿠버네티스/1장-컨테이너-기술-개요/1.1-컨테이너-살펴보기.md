# 1.1 컨테이너 살펴보기

## 1.1.1 컨테이너 실행

> 🧩 **한 줄 요약** — 컨테이너는 **호스트 OS 위에 격리된 앱 실행 환경**을 만드는 기술. `docker run` 한 줄로 실행하면, 호스트와 분리된 독립 공간에서 앱이 돈다.

- **컨테이너** = OS 위에 독립적인 앱 실행 환경을 만드는 기술.
- 하나의 호스트가 **여러 컨테이너**를 가질 수 있고, 각 실행 환경은 **호스트 OS와 격리**된다.
- 실행: 도커 CLI(`docker run ...`)로 실행하면 호스트와 컨테이너는 **서로 격리된 실행 환경**이 된다.
- 격리의 정체: 별도 OS를 띄우는 게 아니라, 호스트 커널을 공유하되 **프로세스·네트워크·파일시스템을 가벽으로 나눈** 것(→ 1.2의 네임스페이스).

## 1.1.2 컨테이너 이미지

> 🧩 **한 줄 요약** — **이미지**는 컨테이너를 찍어내는 "붕어빵 틀" — 앱·의존 파일·실행 설정을 한 덩어리로 묶은 것. **빌드(만들기) → 쉽(레지스트리에 배포) → 런(실행)** 흐름으로 다룬다.

- **이미지** = 컨테이너를 실행하기 위한 템플릿. 담기는 것: 실행할 **앱** + **의존 파일** + **실행 환경 설정 정보**.
- 이미지 하나로 어디서든 **똑같은 컨테이너**를 재현할 수 있다(이식성의 핵심).

### Build · Ship · Run

| 단계 | 뜻 | 도커 명령(예) |
|---|---|---|
| **Build** | 이미지 작성 | `docker build` |
| **Ship** | 이미지 배포(레지스트리에 push) | `docker push` |
| **Run** | 이미지로 컨테이너 실행(pull 후) | `docker run` |

### 레지스트리
- 작성된 이미지를 **다른 머신과 공유**할 수 있게 저장·배포하는 서버(예: Docker Hub).
- 흐름: **빌드용 머신에서 이미지 작성 → 레지스트리 업로드(push) →** 서비스·테스트 환경에서 **가져와(pull) 컨테이너 실행**.

### 자주 쓰는 실행 옵션

| 옵션 | 역할 |
|---|---|
| `--rm` | 컨테이너가 종료되는 즉시 자동 삭제(찌꺼기 안 남김) |
| `-i` | 키보드 입력을 컨테이너로 전달하도록 연결을 계속 열어둠(interactive) |
| `-t` | 가상 터미널(TTY) 할당 — 프롬프트·색상이 진짜 터미널처럼 보이게 |

> 💡 `-i`와 `-t`는 보통 **`-it`로 합쳐 써서** "대화형 터미널로 컨테이너에 들어가기"에 쓴다. 예) `docker run -it ubuntu bash`
