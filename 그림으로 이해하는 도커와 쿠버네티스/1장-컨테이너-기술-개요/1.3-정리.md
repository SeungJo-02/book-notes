# 1.3 정리

> 📝 **Notion 원본**: https://app.notion.com/p/3c5d7d6851ff8170a0aaf3b3a5dd51da

> 🧩 **한 줄 요약** — 컨테이너는 **호스트 OS 커널을 통해 앱을 격리**하는 기술이고, 이를 실행·관리하는 도구가 **도커(단일 머신)**와 **쿠버네티스(다중 머신)**. 다루는 흐름은 **Build → Ship(push) → Run(pull)**.

## 1. 컨테이너 = 커널로 앱을 나눈 것
- 컨테이너는 **호스트 OS의 커널**(SW와 HW를 잇는 역할)을 이용해, OS 위에서 애플리케이션을 **격리해 나누는** 방법.

## 2. 실행 도구 — 도커 vs 쿠버네티스

| 도구 | 범위 |
|---|---|
| **도커** | **단일 머신**(한 컴퓨터)에서 컨테이너 실행·관리 |
| **쿠버네티스** | **다중 머신**(여러 컴퓨터=클러스터)에 걸쳐 컨테이너 오케스트레이션 |

## 3. 다루는 흐름 — Build · Ship · Run

| 단계 | 내용 |
|---|---|
| **Build** | 이미지 작성 — 컨테이너에서 쓸 각종 환경(앱·의존·설정)을 담음 |
| **Ship** | push — 레지스트리(이미지 저장소)에 저장·배포 |
| **Run** | pull 후 실행 — 레지스트리에서 이미지를 가져와 컨테이너로 실행 |

## 🔁 셀프 체크
1. 컨테이너가 앱을 격리할 때 이용하는 것은?
2. 도커와 쿠버네티스의 차이는?
3. Build·Ship·Run에서 레지스트리는 어느 단계에 관여하나?

<details>
<summary>답</summary>

1. 호스트 OS의 커널.
2. 도커는 단일 머신에서, 쿠버네티스는 여러 머신(클러스터)에 걸쳐 컨테이너를 관리한다.
3. Ship(push로 저장)과 Run(pull로 가져옴) 두 단계에서 레지스트리를 거친다.
