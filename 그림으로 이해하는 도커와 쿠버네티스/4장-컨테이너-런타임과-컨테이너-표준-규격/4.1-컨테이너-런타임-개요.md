# 4.1 컨테이너 런타임 개요

> 📝 **Notion 원본**: https://app.notion.com/p/3c5d7d6851ff814b9471c7cf1c62473a

## 4.1.1 도커, 쿠버네티스, 컨테이너 런타임의 관계

> 🧩 **한 줄 요약** — **컨테이너 런타임**은 도커·쿠버의 지시를 받아 실제로 컨테이너를 만드는 소프트웨어. 도커는 도커데몬 → OCI 런타임, 쿠버는 CRI 런타임 → OCI 런타임 경로를 쓰는데, 둘 다 최종적으로 **OCI 표준 런타임**을 쓰기에 도커로 만든 이미지를 쿠버도 그대로 쓸 수 있다.

### 1. 컨테이너 런타임이란
- 도커·쿠버 같은 상위 **오케스트레이터의 지시**를 받아, 머신에 컨테이너를 작성·관리하는 SW.

### 2. 도커 vs 쿠버의 런타임 경로

| 단계 | 도커 | 쿠버 |
|---|---|---|
| 명령 처리 | **도커데몬** (docker 명령 실행, 컨테이너·이미지·네트워크·볼륨 관리) | **CRI 런타임** (파드·이미지·네트워크 관리, 레지스트리 통신) |
| 컨테이너 생성 | **OCI 런타임** | **OCI 런타임** |

- 도커데몬/CRI 런타임이 **실행 설정 + 루트 파일시스템**을 OCI 런타임에 넘겨 컨테이너를 만든다.

### 3. OCI 덕분에 상호 운용
- 도커·쿠버 모두 같은 방식으로 레지스트리에서 이미지를 가져와 OCI 런타임으로 실행 → `docker build`로 만든 이미지를 **쿠버도 그대로 사용 가능**. 전부 **OCI 규격** 덕분.

## 4.1.2 두 종류의 런타임 레이어

> 🧩 **한 줄 요약** — 컨테이너 생성은 **2계층**이다. **고수준 런타임**(도커·CRI 런타임)은 이미지·네트워크 등을 관리하고, **저수준(OCI) 런타임**은 실제 격리 환경을 만든다. OCI=이미지 생성·실행 표준, CRI=kubelet↔런타임 통신 표준.

### 1. 고수준 vs 저수준 런타임

| 축 | 고수준 런타임 | 저수준(OCI) 런타임 |
|---|---|---|
| 역할 | 컨테이너·이미지·네트워크 등 **관리** | 지시를 받아 **격리 환경을 실제로 생성·조작** |
| 예 | docker, CRI 런타임 | (OCI 규격 준수 런타임) |

### 2. 두 표준 — OCI vs CRI
- **OCI** : 컨테이너 이미지를 어떻게 만들고 어떻게 실행할지 정해둔 **산업 표준 규격**.
- **CRI** : kubelet이 컨테이너 런타임에게 "컨테이너 켜/꺼"라고 명령할 때 쓰는 **통신 표준 API**.

## 4.1.3 CRI 런타임, OCI 런타임 연동과 파드 작성 흐름

> 🧩 **한 줄 요약** — 파드 생성 흐름: **kubelet**이 파드 변경을 감지 → **CRI 런타임**(gRPC)에 지시 → 이미지 가져오고 **CNI**로 네트워크 생성 → CRI가 **OCI 런타임**에 넘김 → OCI가 컨테이너를 만들고 앱을 실행. (예: CRI=containerd, OCI=runc)

### 1. 등장 인물 (예시)
- 고수준 런타임(CRI) : **containerd**
- 저수준 런타임(OCI) : **runc**

### 2. 파드 작성 흐름
1. **kubelet**이 파드 변경 감지 → 해당 노드에서 **CRI 호출** (gRPC API, 규격은 CRI)
2. CRI 런타임이 레지스트리에서 **이미지 가져오기** / 컨테이너 작성 준비
3. **CNI**로 파드용 네트워크 인터페이스 작성
4. 하나의 파드에서 **실행 환경 설정 파일**에 반영
5. CRI가 설정 파일 + 이미지의 루트 파일시스템을 **OCI에 넘겨** 컨테이너 실행 환경 작성 지시 (규격: OCI Runtime Specification)
6. **OCI 런타임**이 컨테이너를 만들고 그 안에서 앱 실행

- 컨테이너 작성하는 흐름
  - 고수준 런타임
    - 컨테이너, 이미지, 네트워크 등 관리 담당
      - docker : 도커
      - K8s : CRI 런타임
  - 저수준(OCI) 런타임
    - 고수준 런타임에서 지시를 받아서 격리 환경을 컨테이너로 만들고 조작하는 수단 제공
    - 규격은 OCI
- OCI : 컨테이너 **이미지를 어떻게 만들고 어떻게 실행할지 정해둔 산업 표준 규격**
- CRI : Kubelet 가 컨테이너 런타임(도커 등)에게 "컨테이너 켜! 꺼!"라고 명령을 내릴 때 사용하는 통신 표준 API

**4.1.3 CRI 런타임, OCI 런타임 연동과 파드 작성 흐름**
- 고수준 런타임(CRI) : containerd
- 저수준 런타임(OCI) : runc
- Kubelet이 파드 변경 감지 → 변경이 감지된 노드에서 CRI 호출 <br>(Kubelet이 이 때 CRI 런타임에 gRPC API를 사용해서 지시, API는 CRI로 쿠버에 정의)
- → CRI 런타임이 레지에서 이미지 가져오기 혹은 컨테이너 작성준비 on
- → CNI를 이용해서 파드용 네트워크 인터페이스도 작성한다
- → 하나의 파드에서 실행 환경 설정 파일에 반영
- → CRI 가 실행 환경 설정 파일과 이미지의 루트파일 시스탬을 OCI로 텀겨서 컨테이너 실행 환경 작성 지시<br>규격은 OCI runtime specification에서 정함
- → OCI 런타임이 컨테이너를 작성하고 이후 안에 APP을 실행
