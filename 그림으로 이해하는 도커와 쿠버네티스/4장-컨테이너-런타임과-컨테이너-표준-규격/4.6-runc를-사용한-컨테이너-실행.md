# 4.6 runc를 사용한 컨테이너 실행

> 📝 **Notion 원본**: https://app.notion.com/p/3c5d7d6851ff81eb9dbbf6ca324e1d24

## 4.6.1 컨테이너 이미지를 가져오고 컨테이너 기반 작성

> 🧩 **한 줄 요약** — **runc**는 서브 명령어로 OCI Runtime Spec을 구현한다. 상위 도구(고수준 런타임)가 runc 서브 명령어를 호출해 컨테이너를 조작하며, 컨테이너 생성 재료는 **번들**(루트 파일시스템 + 실행 환경 설정 파일)이다.

- **상위 도구**(고수준 런타임)가 runc 서브 명령어와 함께 실행해 컨테이너를 조작한다.
- **runc** : 서브 명령어로 OCI Runtime Specification을 구현.
- **번들** 구성 :
  - **루트 파일시스템** : 컨테이너 작성 시 필요한 데이터를 저장하는 디렉터리.
  - **실행 환경 설정 파일** : 컨테이너를 어떻게 띄울지 담은 설정.

## 4.6.2 컨테이너 실행

> 🧩 **한 줄 요약** — OCI의 **create/start** 동작은 각각 **runc create / runc start** 서브 명령어로 실행된다. 고수준 런타임도 runc를 쓸 때 이 서브 명령어를 사용한다.

| OCI 동작 | runc 서브 명령어 | 의미 |
|---|---|---|
| create | `runc create` | 컨테이너 작성 |
| start | `runc start` | 컨테이너 실행 시작 |

- 고수준 런타임이 runc를 사용할 때도 위 서브 명령어를 그대로 쓴다.

## 4.6.3 컨테이너 정지와 삭제

> 🧩 **한 줄 요약** — OCI의 **kill/delete** 동작은 각각 **runc kill / runc delete** 서브 명령어로 실행된다.

| OCI 동작 | runc 서브 명령어 | 의미 |
|---|---|---|
| kill | `runc kill` | 컨테이너 정지 |
| delete | `runc delete` | 컨테이너 삭제 |

> 💡 컨테이너 생명주기 create → start → kill → delete가 모두 runc 서브 명령어와 1:1로 대응한다(4.5.1 OCI Runtime Spec의 동작들).
