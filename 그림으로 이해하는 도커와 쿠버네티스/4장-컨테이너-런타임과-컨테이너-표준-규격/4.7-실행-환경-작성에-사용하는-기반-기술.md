## 4.7.1 네임스페이스

> 🧩 **한 줄 요약** — **네임스페이스**는 프로세스가 보는 리소스를 다른 프로세스와 **격리**하는 커널 기능. 종류별로 PID·Mount·Network·UTS·IPC·User를 격리해, 컨테이너에 "이 컴퓨터를 나 혼자 쓴다"는 환상을 준다. 목적은 **충돌 방지 + 보안**.

### 1. 네임스페이스 종류

| 종류 | 격리 대상 |
|---|---|
| **PID** | 프로세스 그룹 |
| **Mount** | 마운트 포인트 목록 |
| **Network** | 네트워크 관련 리소스 |
| **UTS** | 호스트명 등 |
| **IPC** | 프로세스 간 통신 리소스 |
| **User** | 사용자/그룹·권한 |

- 호스트 OS에겐 그냥 일반 프로세스 하나지만, 컨테이너 내부에는 "내가 이 컴퓨터의 유일한 주인"이라는 환상을 심어주는 **논리적 격리** 기술.

### 2. 왜 쓰나 — 충돌 방지 + 보안
- 모든 앱이 서버를 혼자 쓴다고 착각하게 만들어 서로의 영역을 침범하지 못하게 한다.
- **포트 충돌 해결** : 80번 포트를 쓰는 Nginx를 한 서버에 5개 동시에 (가상 랜카드를 각각 부여).
- **보안 격리** : A 컨테이너가 해킹당해도 B 컨테이너·호스트 파일은 못 들여다보게 차단.

## 4.7.2 cgroup

> 🧩 **한 줄 요약** — **cgroup**은 프로세스(컨테이너)가 쓰는 자원(CPU·메모리·디바이스 접근)을 **제한**하는 커널 기능. 컨테이너에 '목줄'을 채워 **Noisy Neighbor**(한 컨테이너의 자원 독식)를 막는다. 쿠버 yaml의 `limits`가 cgroup으로 전달된다.

### 1. 무엇을 제한하나
- 디바이스 파일 접근 권한 · CPU 제한 · 메모리 사용량 제한.
- 리소스는 **서브시스템/리소스 컨트롤러**로 관리되고, 설정은 **cgroup 파일시스템**을 통해 이뤄진다. (v1=현재 사용, v2=향후)

### 2. 왜 쓰나 — Noisy Neighbor 방지
- 특정 컨테이너가 서버 자원을 혼자 독식해 다른 멀쩡한 서비스까지 다운시키는 상황을 막는다.
- **자원 제한** : 쿠버 yaml에 `memory: "512Mi"` 같은 `limits`를 걸면, 이 설정이 cgroup을 통해 커널에 전달돼 물리적 통제가 된다.
- **비용·계측(Metering)** : 서비스별 CPU·메모리 사용량을 측정해 과금·모니터링에 쓴다.

> 💡 **네임스페이스(격리) vs cgroup(제한)** — 네임스페이스는 리소스를 "격리"하고, cgroup은 리소스 사용량을 "제한"한다.

2. cgroup이 제한하는 자원의 예와, Noisy Neighbor 문제란?
3. 쿠버 yaml의 `limits`는 어떻게 실제 제한이 되나?

- 왜 사용?
  - 충돌 방지'와 '보안' 모든 앱이 자기가 서버를 혼자 쓰고 있다고 착각하게 만들어서, 서로의 영역을 침범하지 못하게 막는 역할
  - e.g.
    - **포트 충돌 해결:** 한 서버에 80번 포트를 사용하는 웹 서버(Nginx)를 5개 동시에 띄워야 할 때. (가상의 랜카드를 각각 부여하여 충돌 없이 돌아가게 해 줍니다.)
    - **보안 격리:** A 컨테이너가 해킹당해 관리자 권한을 뺏기더라도, B 컨테이너나 호스트 서버의 파일은 절대 들여다볼 수 없게 차단해야 할 때.

**4.7.2 cgroup**
- 프로세스가 사용할 수 있는 리소스에 다양한 설정을 하는 기능
  - 디바이스 파일에 접근 권한
  - 프로세스에서 사용할 수 있는 CPU 제한
  - 프로세스가 사용할 수 있는 메모리 사용량 제한
- 리소스는 서브시스템, 리소스 컨트롤러의 컴포넌트로 관리됨
  - 컨트롤러에 대한 설정은 cgroup 파일 시스템을 통해서 이루어짐
    - v1(현재 사용)
    - v2(아직 사용안함)
- 즉, 컨테이너에 '목줄'을 채워서 밥(CPU, 메모리)을 정해진 양만 먹게 하는 것
  - 왜 사용?
    - Noisy Neighbor : 한 놈이 자원을 독식하는 경우
    - 특정 컨테이너가 서버 자원을 혼자 독식해서 다른 멀쩡한 서비스들까지 다운시키는 최악의 상황을 방지
  - e.g.
    - **자원 사용량 제한 설정 (`limits`):** 개발자가 쿠버네티스 yaml 파일에 `memory: "512Mi"`라고 제한을 걸 때, 이 설정이 바로 cgroup을 통해 커널에 전달되어 물리적 통제로 이어집니다.
    - **비용 및 계측(Metering):** 여러 서비스가 각각 CPU와 메모리를 얼마나 사용했는지 정확하게 측정해서 클라우드 과금을 하거나 모니터링을 해야 할 때.
