# 3.3 쿠버네티스의 기본 배포 단위: 파드

## 3.3.1 파드와 컨테이너

> 🧩 **한 줄 요약** — **파드**는 쿠버의 최소 배포 단위로 1개 이상의 컨테이너를 묶는다. 같은 파드의 컨테이너들은 같은 노드·네트워크·스토리지를 공유하고 내부는 `localhost`로 통신한다. 보통 컨테이너 1개당 앱 1개를 넣고, 보조 기능은 **사이드카**로 붙인다.

### 1. 파드 = 쿠버의 최소 배포 단위
- 쿠버 = 컨테이너 그룹을 관리하는 **오케스트레이터**. 앱은 컨테이너로 실행된다.
- **파드** : 1개 이상의 컨테이너를 한 번에 묶어 관리하는 배포 단위 (도커는 컨테이너 1개 단위)
- 같은 파드의 컨테이너들은 **같은 노드**에 배치되고 **네트워크 인터페이스·스토리지를 공유**한다.

| 통신 | 방식 |
|---|---|
| 파드 ↔ 파드 | IP는 **파드마다** 할당 → 서로 다른 IP로 통신 |
| 파드 내부 컨테이너끼리 | `localhost`로 통신 (같은 네트워크 공유) |

### 2. 컨테이너 구성 원칙
- 보통 **컨테이너 1개 = 앱 1개** (DB · 메시지 큐 · 웹 서버 · API 서버 등)
- 여러 앱을 한 컨테이너에 몰면 안 됨 → 스케일 아웃이 어렵고, 하나가 죽으면 전부 참사
- 관련 있는 앱은 한 컨테이너가 아니라 **한 파드로 묶어** 다룬다

### 3. 멀티 컨테이너 디자인 패턴

| 패턴 | 역할 |
|---|---|
| **사이드카** | 메인 컨테이너 기능을 확장하는 컨테이너를 같은 파드에 배치 (예: 로그 수집) |
| **앰배서더** | 파드가 외부와 통신할 때 대리 프록시 역할 |
| **어댑터** | 메인 컨테이너 출력을 외부가 원하는 표준 형식으로 변환 |

## 3.3.2 레이블과 애너테이션

> 🧩 **한 줄 요약** — MSA로 관리 대상이 많아지면 **레이블·애너테이션**(둘 다 키-값)으로 그룹화하고 정보를 붙인다. **레이블**은 **셀렉터**로 골라낼 수 있지만, **애너테이션**은 셀렉터 대상이 아니라 도구용 부가 정보에만 쓴다.

### 1. 왜 필요한가
- MSA로 가면 파드·관리 대상이 너무 많아진다 → 그룹화하고 적절한 추가 정보를 부여할 방법이 필요.
- 그 수단이 **레이블**과 **애너테이션** — 둘 다 **키-값** 형태로 파드·다양한 관리 대상에 붙인다.

### 2. 레이블 vs 애너테이션

| 축 | 레이블 (Label) | 애너테이션 (Annotation) |
|---|---|---|
| 형태 | 키-값 | 키-값 |
| 용도 | 관리 대상 **그룹화·식별** | 컴포넌트·주변 도구용 **부가 정보** |
| 셀렉터 | 셀렉터로 선별 가능 | **셀렉터 불가** |

- **셀렉터** : 레이블을 붙인 관리 대상을 선별(필터)할 때 쓰는 것.

## 🔁 셀프 체크

3. 특정 파드 그룹만 골라내려면 레이블과 애너테이션 중 무엇을 쓰며, 그 이유는?
