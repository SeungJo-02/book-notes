# 3.1 쿠버네티스의 특징

> 📝 **Notion 원본**: https://app.notion.com/p/3c5d7d6851ff81f6a66bc29ad69582d6

## 3.1.1 파일을 사용한 선언적 관리

> 🧩 **한 줄 요약** — 쿠버네티스는 "이런 상태가 되어야 한다"를 YAML/JSON **매니페스트** 파일에 적어두면(선언형), 쿠버가 현재 상태를 그 목표에 맞춰준다. 절차를 하나하나 지시하는 명령형과 반대다.

### 1. 선언적 관리 (Declarative)
- **선언형** : 목표 상태("파드는 항상 3개")만 적으면 쿠버가 알아서 맞춤
- **명령형** : "파드 실행 → 하나 더 → 하나 더" 절차를 직접 지시

| 축 | 명령형 (Imperative) | 선언형 (Declarative) |
|---|---|---|
| 적는 것 | 도달 절차 | 최종 목표 상태 |
| 예 | `kubectl run` 반복 | 매니페스트에 `replicas: 3` |
| 복구 | 사람이 다시 지시 | 쿠버가 자동으로 목표에 수렴 |

### 2. 매니페스트 (Manifest)
- **정의** : 쿠버를 실행하기 위한 선언적 주문서이자 설계도. YAML/JSON으로 작성.
- **담는 것** : 실행할 컨테이너 수, 배포 형식, 스토리지, 필수 통신 엔드포인트 등
- **장점** : Git으로 버전 관리 가능 · 과거 상태로 롤백이 쉬움

#### 매니페스트 예시 (YAML)

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
spec:
  replicas: 3          # 목표: 파드는 항상 3개
  template:
    spec:
      containers:
        - name: web
          image: nginx:latest
```

## 3.1.2 광범위한 배포 형식 지원

> 🧩 **한 줄 요약** — 쿠버는 상태 없는 앱(스테이트리스)과 상태를 유지하는 앱(스테이트풀)을 모두 배포할 수 있고, 자동 복구·스케일링·업데이트 관리 같은 운영 기능을 기본으로 제공한다.

### 1. 배포 형식 — 스테이트리스 vs 스테이트풀

| 축 | 스테이트리스 (Stateless) | 스테이트풀 (Stateful) |
|---|---|---|
| 데이터 | 컨테이너 종료와 함께 폐기, 상태 유지 안 함 | 상태(데이터)를 유지 |
| 예 | 웹 서버, API 서버 | DB, 메시지 큐 |
| 쿠버 리소스 | 디플로이먼트 | 스테이트풀셋 (→ 3.4.2) |

### 2. 쿠버가 기본 제공하는 운영 기능
- **자동 복구** (self-healing) : 파드가 죽으면 알아서 다시 띄움
- **스케일링** : 부하에 맞춰 파드 수를 늘리고 줄임
- **업데이트 관리** : 새 버전 배포·롤백을 관리

## 3.1.3 확장성이 뛰어난 아키텍처와 활발한 개발자 커뮤니티

> 🧩 **한 줄 요약** — 쿠버의 모든 관리 정보는 HTTP API로 공개되고, 사용자는 `kubectl`로 API를 호출해 "이상적인 상태"를 선언한다. **컨트롤러**가 그 API를 보고 실제 상태를 목표에 맞추며, **커스텀 리소스**로 API 자체도 확장할 수 있다.

### 1. API 중심 아키텍처
- 쿠버의 관리 정보는 전부 **HTTP API**로 공개된다.
- 사용자는 API를 조작해 이상적인 상태를 선언하거나 앱 상태를 확인한다.
- `kubectl` = 이 API를 쉽게 날려주는 명령어 (즉, kubectl로 API를 보내 관리한다는 말).

### 2. 확장·교체 포인트
- **컨트롤러** : API를 참조·조작해 구체적 관리를 수행하는 컴포넌트. 예) 사용자가 정의한 이상적 상태를 유지하도록 컨테이너 실행 개수를 맞춤.
- **커스텀 리소스** : API 자체를 확장해 쿠버에 없는 새로운 관리 대상을 정의하는 기능.
- 컴포넌트·런타임 등도 교체 가능 → 확장성이 높은 구조.

## 🔁 셀프 체크
1. 선언적 관리가 무엇이며, 명령형 대신 선언형으로 관리하면 어떤 이점이 있나?
2. DB처럼 데이터를 유지해야 하는 앱은 어떤 배포 형식/리소스로 다루나?
3. 컨트롤러의 역할은 무엇이며, 커스텀 리소스란 무엇인가?
