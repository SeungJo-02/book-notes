# 3.2 쿠버네티스 클러스터와 kubectl

> 🧩 **한 줄 요약** — 쿠버 **클러스터**는 여러 **노드**(머신)의 집합이고, 그 두뇌인 **컨트롤 플레인**(API 서버·컨트롤러·스케줄러)이 클러스터를 관리한다. 사용자는 `kubectl`로 API 서버에 명령을 보낸다.

## 1. 클러스터의 구성

| 구성요소 | 설명 |
|---|---|
| **클러스터** | 컨테이너 그룹을 실행하는 노드(머신)들의 집합 |
| **노드** | 컨테이너가 실제로 실행되는 머신(여러 컨테이너를 싣는 가상 서버) |
| **컨트롤 플레인** | 클러스터를 관리하는 두뇌 (원본의 "컨트롤 브레인") |

> 💡 원본의 **"컨트롤 브레인"**의 정식 명칭이 **컨트롤 플레인(Control Plane)**이다.

## 2. 컨트롤 플레인 컴포넌트
- **API 서버** : 모든 조작의 입구. `kubectl`이 여기로 요청을 보낸다.
- **컨트롤러** : 컨테이너 실행 개수 유지 등 기본 관리를 담당.
- **스케줄러** : 컨테이너(파드)를 어느 노드에 배포할지 스케줄링.

## 3. kubectl 기본 명령
- **디플로이먼트** : 매니페스트에 "클러스터가 유지할 규칙"을 적어두는 리소스 (자세히는 → 3.4.1)
- **kubectl** : API 서버 조작을 쉽게 해주는 명령어

```bash
kubectl apply -f deploy.yaml   # 매니페스트를 클러스터에 선언 (-f = file)
kubectl get deployments        # 배포(디플로이먼트) 상태 조회
kubectl delete -f deploy.yaml  # 리소스 삭제
```

2. 컨트롤 플레인의 세 컴포넌트(API 서버·컨트롤러·스케줄러)는 각각 무슨 일을 하나?
3. `kubectl apply -f`에서 `-f`는 무엇을 뜻하나?

<summary>답</summary>

1. 클러스터는 노드(머신)들의 집합이고, 노드는 그 안에서 컨테이너가 실제로 실행되는 개별 머신이다.
2. API 서버는 모든 조작의 입구, 컨트롤러는 실행 개수 유지 등 상태 관리, 스케줄러는 파드를 어느 노드에 배치할지 결정한다.
3. file — 뒤에 오는 매니페스트 파일을 지정해 그 내용을 클러스터에 선언한다는 뜻.

**3.2 쿠버네티스 클러스터와 kubectl**
- 클러스터 : 컨테이너 그룹을 실행하는 머신집합(노드들을 모아둔 거 )
- 노드 : 각 컨테이너가 실행되는 머신(여러 컨테이너를 싣는 가상서버)
- 컨트롤 브레인 : 쿠버 클러스터를 관리하는 컴포넌트 (클러스터의 두뇌)
  - e.g. : API 서버 등등
  - 컨트롤러 : 기본적인 관리 - 컨테이터 실행 개수 유지
  - 스케줄러 : 컨테이터 배포 스케줄링 등등
- 디플로이먼트 : 매니페스트에 클러스터의 규칙을 적어두는 것
- kubectl : API 조작을 쉽게 해주는 명령어
- 메니페스트를 쿨러스터에 선언하려면 -f 사용하기 kubectl apply -f
- kubectl get
- kubectl deployments
- kubectl delete

</details>
