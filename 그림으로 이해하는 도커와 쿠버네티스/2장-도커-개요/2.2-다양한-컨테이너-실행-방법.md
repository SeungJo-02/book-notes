# 2.2 다양한 컨테이너 실행 방법

## 2.2.1 호스트와 컨테이너의 파일 공유와 데이터 유지

> 🧩 **한 줄 요약** — 컨테이너 파일시스템은 격리돼 있어 **삭제하면 데이터도 사라진다.** 이를 넘어 데이터를 공유·유지하는 두 방법이 **바인드 마운트**(호스트 폴더 직결)와 **볼륨**(도커가 관리하는 창고).

- 컨테이너 루트 파일시스템은 호스트와 **격리** — 삭제하면 안의 데이터도 소실. 그래서 밖에 두고 연결하는 기능이 필요.

| 구분 | 바인드 마운트 | 볼륨(Volume) |
|---|---|---|
| 연결 대상 | **내가 지정한 호스트 폴더** | **도커가 관리하는 저장소**(이름 지정) |
| `-v` 인수 | 호스트 경로:컨테이너 경로 | 볼륨명:컨테이너 경로 |
| 주 용도 | 개발 중 **코드 실시간 반영** | 컨테이너 간 공유 · **삭제 후 데이터 유지** |

```bash
docker run -v /Users/my/code:/app 이미지   # 바인드 마운트(실시간 반영)
docker run -v my-shared-vol:/app 이미지     # 볼륨(삭제해도 데이터 유지)
```

- 관리: `docker volume ls` / `docker volume rm 볼륨명`. **같은 볼륨을 쓰는 컨테이너끼리만** 공유.

## 2.2.2 컨테이너 포트를 호스트에서 공개하기

> 🧩 **한 줄 요약** — 컨테이너는 IP가 달라 기본적으로 호스트 포트로 통신 못 한다. **`-p 호스트포트:컨테이너포트`**로 **포트 포워딩**을 열면 요청이 컨테이너로 연결된다. 바인딩 IP를 지정하면 보안도 챙긴다.

```bash
docker run -p 8080:80 nginx
```
- 흐름: `localhost:8080` 접속 → 도커 엔진이 `8080:80` 규칙 확인 → Nginx 컨테이너 80번으로 전달.

| 표기 | 의미 |
|---|---|
| `-p 8080:80` | 도커가 몰래 `0.0.0.0:`을 붙임 → **모든 외부에 개방** |
| `-p 127.0.0.1:8080:80` | **내 컴퓨터 내부에서만** 접속 허용(외부 차단) |

> ⚠️ **DB 포트 사고** — `-p 3306:3306`은 DB를 전 세계에 개방(해킹 위험). `-p 127.0.0.1:3306:3306`으로 내부 백엔드만 접근하게 막아야 한다.

## 2.2.3 컴포즈 — 여러 컨테이너를 한꺼번에

> 🧩 **한 줄 요약** — **컴포즈**는 연관된 **여러 컨테이너를 한 머신에서 한꺼번에** 정의·실행하는 기능. **YAML 파일** 하나에 적어두고 `up`/`down`으로 통째로 켜고 끈다.

- 기본 도커는 컨테이너 하나 단위, 컴포즈는 **한 머신의 여러 컨테이너**(웹+DB+캐시 등)를 묶음.

| 명령 | 역할 |
|---|---|
| `docker compose build` | 파일에 지정한 빌드 실행 |
| `docker compose up` | 파일 속 컨테이너 전부 실행 |
| `docker compose down` | 파일 속 컨테이너 전부 정지·삭제 |
