# 2.4 컨테이너 레이어 구조

> 🧩 **한 줄 요약** — 이미지는 **변경사항(레이어)들을 겹쳐 쌓은** 것(Union File System). 실행 시 맨 위에 **빈 R/W 레이어**를 얹고, 읽기 전용 이미지 레이어는 **공유**한다. 수정 시엔 그 파일만 복사해 올리는 **Copy on Write(CoW)**.

## 2.4.1 이미지의 레이어 구조
- 이미지 = 레이어(투명 필름)들의 집합. 겹친 결과가 컨테이너의 루트 파일시스템(**Union File System**).

| 단계 | 레이어 동작 |
|---|---|
| Build | 명령마다 레이어를 쌓아 이미지 작성 |
| Ship | 레이어 단위 업/다운로드 — 이미 있는 건 빼고 **바뀐 것만** push/pull |
| Run | 이미지 레이어 위에 **R/W 레이어**를 얹어 실행 |

> 실행 중 쓰기·삭제는 전부 맨 위 R/W 레이어에만 → 아래 이미지 레이어는 읽기 전용이라 훼손 안 됨.

## 2.4.2 이미지 내부 내용 보기
- 이미지 tar를 풀면 **`manifest.json`**(조립 설명서, 레이어 순서) + **레이어별 폴더**(각 `layer.tar`).
- 실행 시 manifest 순서대로 레이어를 중첩 → 루트 파일시스템 완성.

## 2.4.3 빌드와 레이어 구조 — 캐시 순서 ⭐
- `FROM` 위에 명령마다 변경사항을 겹겹이 쌓음. 각 레이어는 **캐시**됨 → 다음 빌드 땐 바뀐 부분(과 그 아래)만 재빌드.

> 🔑 **핵심 요령** — **자주 바뀌는 명령을 도커파일 아래쪽에** 두라. 위쪽(의존성 설치 등)이 캐시로 재사용돼 빌드가 빨라진다. (그래서 `COPY package.json → RUN install`을 먼저, `COPY . .`을 뒤에)

## 2.4.4 실행의 레이어 구조 — CoW
- 이미지 레이어는 **읽기 전용으로 공유**, 컨테이너마다 맨 위에 **R/W 레이어**.
- **Copy on Write** — 읽기 전용 파일을 수정하려 하면 그 파일만 R/W 레이어로 복사해 거기서 고침.

> 컨테이너를 100개 띄워도 **원본 이미지는 HDD에 하나**(읽기 전용). 나머지는 공유, 쓰기는 각자의 R/W 레이어 → 스토리지 효율↑.

## 2.4.5 필요한 기술 — 스토리지 드라이버(overlay2)
- **스토리지 드라이버** = 레이어를 저장·중첩해 루트 파일시스템으로 만드는 컴포넌트. 기본 **overlay2**.
- overlay2: 레이어(tar)를 **압축 풀어 폴더로** 저장 → 오버레이 파일시스템으로 중첩.

| 구성 | 역할 |
|---|---|
| **LowerDir** | 이미지 레이어 — **읽기 전용** |
| **UpperDir** | 컨테이너용 새 폴더 — **쓰기 가능** |
| **Merged** | Lower+Upper를 겹쳐 본 최종 루트 파일시스템(컨테이너가 보는 것) |

- 작동: 생성→Upper에 쓰기 / 삭제→Upper에 whiteout 스티커 / 수정→CoW.

## 🔁 셀프 체크
1. 여러 컨테이너가 같은 이미지를 쓰면 레이어는 복사되나 공유되나?
2. 자주 바뀌는 명령은 도커파일 어디에 두어야 하나?
3. LowerDir·UpperDir·Merged는 각각 무엇인가?

**2.4.3 빌드와 레이어**
- 도커 파일 이미지 작성 순서와 관련. FROM 위에 각 명령 변경사항을 겹쳐 쌓아 빌드

  ```
  1. FROM ubuntu:20.04       👈 [바닥 뼈대] 우분투 운영체제 필름을 깝니다.
  2. RUN apt-get install git 👈 [1층] 깃(Git) 프로그램을 설치한 필름을 덮습니다.
  3. COPY . /app             👈 [2층] 내 소스 코드를 복사한 필름을 덮습니다.
  4. RUN npm run build       👈 [3층] 코드를 빌드한 결과물 필름을 덮습니다.
  ```
- 명령 실행마다 캐시. 다음 빌드 땐 변경사항만. 중요한 건 자주 바뀌는 명령을 도커파일 아래에 적는 것

**2.4.4 실행의 레이어**
- 실행 시에도 레이어 구조 유지. 이미지 레이어는 읽기 전용·공유, 컨테이너마다 R/W 레이어
- Copy on Write : 읽기 전용 파일 변경 시 그 파일만 복사해 위로 올려 수정. 데이터 중복 없음
- 컨테이너 100개여도 원본 이미지만 HDD에 저장(읽기 전용), 쓰기는 각 R/W 레이어

**2.4.5 필요한 기술**
- 스토리지 드라이버 : 레이어를 호스트에 저장·중첩해 루트 파일시스템으로 사용(overlayfs/btrfs). 기본 overlay2
  - 레이어(tar)를 압축 풀어 폴더로 저장 → 오버레이 파일시스템으로 중첩
- 오버레이 파일시스템 : LowerDir(이미지, 읽기 전용) / UpperDir(컨테이너용, 쓰기 가능) / Merged(합쳐 본 것, 컨테이너가 진짜 루트로 착각)
  - 생성→Upper에 쓰기 / 삭제→Upper에 스티커 / CoW
