# 2.1 도커와 Build, Ship, Run

## 2.1.1 Build — 컨테이너 이미지 작성

> 🧩 **한 줄 요약** — **Build**는 **도커파일(조립 설명서)**과 **컨텍스트(재료 상자)**를 도커 엔진에 넘겨 **이미지**를 굽는 단계. `docker build -t 이름:태그 <컨텍스트경로>`로 실행한다.

- **이미지** = 컨테이너 기반 데이터 — **바이너리 + 의존 파일 + 실행 환경(OS·런타임) 설정 정보**.
- 재료 두 가지:
  - **도커파일** = 조립 절차를 적은 설명서(명령어 목록)
  - **컨텍스트** = 빌드에 쓰는 파일·소스코드가 담긴 상자
- 흐름: 도커 엔진이 컨텍스트 + 도커파일을 메모리로 가져가 **순서대로** 실행해 이미지 완성.

### 도커파일 핵심 명령

| 명령 | 역할 |
|---|---|
| `FROM` | 뼈대 — 어떤 OS·언어 환경을 밑바탕으로 |
| `WORKDIR` | 작업 폴더 지정 |
| `COPY` | 컨텍스트의 파일을 컨테이너로 복사 |
| `RUN` | 빌드 중 실행(주로 패키지 설치) |
| `CMD` | 컨테이너가 켜질 때 실행할 메인 명령 |

```docker
FROM node:18-alpine     # 뼈대: Node 18 가벼운 리눅스
WORKDIR /app            # 작업 폴더 /app
COPY package.json ./    # 패키지 정보만 먼저 복사
RUN npm install         # 모듈 설치
COPY . .                # 나머지 코드 전부 복사
CMD ["npm", "start"]    # 켜지면 서버 실행
```

### 빌드 실행 — 컨텍스트 경로가 중요

| 명령 | 컨텍스트 |
|---|---|
| `docker build .` | 지금 터미널이 있는 **이 폴더 전체**를 재료로 |
| `docker build ./내이미지` | 특정 **하위 폴더만** 재료로 |

## 2.1.2 Run — 컨테이너 실행

> 🧩 **한 줄 요약** — **Run**은 이미지를 컨테이너로 띄우는 단계. `docker run`으로 실행, `docker exec -it`로 안에 들어가며, `docker stop → rm`으로 정지·삭제.

| 명령 | 역할 |
|---|---|
| `docker run --name 이름 이미지:버전` | 이미지를 컨테이너로 실행 |
| `docker exec -it 컨테이너 sh` | 실행 중 컨테이너에 새 명령 실행(대화식 셸) |
| `docker stop 컨테이너` | 정지 |
| `docker rm 컨테이너` | 삭제 |

- 컨테이너 안에서 `ls`·`ps`로 내부 확인. `systemd`=1번 프로세스(PID 1), `PID`=프로세스 고유 번호.
- **run vs exec**: run은 이미지로 새 컨테이너를 만들어 실행, exec는 이미 켜진 컨테이너 안에서 명령 실행.

## 2.1.3 Ship — 레지스트리를 사용한 배포

> 🧩 **한 줄 요약** — **Ship**은 이미지를 **레지스트리**(예: Docker Hub)에 올려 공유하는 단계. `tag`로 이름 붙이고 → `push`로 올리고 → `pull`로 가져온다.

- **레지스트리** = 이미지 배포 서버 / **리포지토리** = 각 이미지 저장 장소(여러 이미지를 **태그**로 구분).

| 단계 | 명령 |
|---|---|
| 이름 부여 | `docker tag 내이미지:버전 도커허브이름/내이미지:버전` |
| 올리기 | `docker push 도커허브이름/내이미지:버전` |
| 가져오기 | `docker pull 도커허브이름/내이미지:버전` |

**2.1.1 Build**
- 컨테이너 이미지 : 컨테이너 기반 데이터 — 바이너리(코드를 기계어로 번역), 의존파일, 실행환경(OS·런타임) 설정 정보
- 빌드 : 이미지 작성. 이미지 바탕으로 루트파일시스템과 격리된 실행환경을 작성·실행
  - 재료 : 도커파일(컨테이너 작성 절차 기록, 조립 설명서) + 컨텍스트(데이터·소스코드가 담긴 상자)
  - FROM(뼈대) / WORKDIR(작업 공간) / COPY(재료 옮기기) / RUN(조리·설치) / CMD(완성 후 실행)
  - docker 엔진이 컨텍스트+도커파일을 메모리로 가져가 순서대로 실행
  - docker build -t 내이미지:버전 ./내이미지. `docker build .`(현재 폴더 전체) / `docker build ./내이미지`(하위 폴더만)
- 쉽 : 레지스트리 사용 — 푸시(올리기)/풀(가져오기) / 런 : 이미지 실행

**2.1.2 Run**
- docker run —name 컨테이너이름 이미지:버전
- docker exec : 실행 중 컨테이너에 새 명령. -it(대화식 셸). ls/ps로 내부 확인. systemd(1번 프로세스), PID(고유 번호표)
- docker stop 컨테이너 / docker rm 컨테이너

**2.1.3 Ship**
- 레지스트리(이미지 배포용 서버, e.g. 도커허브)를 통해 다른 호스트와 공유. 리포지토리에 여러 이미지 저장, 태그로 구분
- docker tag 내이미지:버전 도커허브이름/내이미지:버전 / docker image ls (확인)
- docker push 도커허브이름/내이미지:버전 (저장) / docker pull (가져오기)
