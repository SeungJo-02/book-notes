# 2.3 도커파일

## 2.3.1 도커파일 기본 문법

> 🧩 **한 줄 요약** — 도커파일은 이미지 작성 절차를 **한 줄에 한 명령**으로 적은 파일. `FROM`으로 베이스를 깔고, `COPY`·`RUN`·`ENV`·`ENTRYPOINT`로 그 위를 쌓아 이미지를 완성한다.

| 명령 | 역할 | 예 |
|---|---|---|
| `FROM` | 베이스 이미지 지정(첫 줄 필수) | `FROM ubuntu:20.04` |
| `COPY` | 컨텍스트의 파일을 이미지로 복사 | `COPY index.html /app/` |
| `RUN` | 빌드 중 셸 명령(주로 설치) | `RUN npm install` |
| `ENV` | 환경 변수 설정(빌드·실행 시 사용) | `ENV PORT=8080` |
| `ENTRYPOINT` | 실행 시 **강제로** 실행할 명령 | `ENTRYPOINT ["node","server.js"]` |

- **이미지 = 루트 파일시스템 + 실행 시 설정.**

> 💡 **CMD vs ENTRYPOINT** — 둘 다 시작 명령이지만, `CMD`는 실행 시 다른 명령으로 **덮어쓸 수 있고**, `ENTRYPOINT`는 사용자가 뭘 쳐도 **무조건 그 프로그램을 실행**한다.

**빌드 중 멈춤 방지** — 설치 중 "예/아니오" 질문이 뜨면 빌드가 멈춘다. `DEBIAN_FRONTEND=noninteractive`로 질문 없이 설치하게 설정.

## 2.3.2 멀티 스테이지 빌드

> 🧩 **한 줄 요약** — **멀티 스테이지 빌드**는 하나의 도커파일에 `FROM`을 여러 번 써서 **빌드용(무거운)과 실행용(가벼운) 스테이지를 분리**하는 것. 최종 이미지는 **맨 마지막 `FROM`** 기준이라 빌드 도구를 빼고 결과물만 담아 **가벼워진다.**

- **Stage** = `FROM`으로 시작하는 독립 빌드 절차(`FROM 이미지 AS 이름`).
- 최종 이미지는 마지막 `FROM` 기준 → 컴파일 도구가 빠져 **경량화**.

| 기능 | 설명 |
|---|---|
| `COPY --from=스테이지` | 지정 스테이지의 결과물만 실행 스테이지로 복사 |
| **빌드킷**(BuildKit) | 의존 관계 분석 → 필요한 스테이지만, 의존 없는 건 병렬 빌드 |

```docker
FROM node AS frontend       # 1번 주방: 웹 빌드(무거움)
RUN npm run build           # → out/ 결과물
FROM rust AS backend        # 2번 주방: 서버 컴파일
RUN cargo build --release   # → server 실행파일
FROM nginx                  # 최종(가벼움): 결과물만 가져옴
COPY --from=frontend /app/out /var/www/html
COPY --from=backend /app/target/release/server /usr/local/bin/server
```

**2.3.1 기본 문법**
- 이미지 작성 절차를 기록한 파일. 명령을 줄단위로 작성
  - FROM : 베이스 이미지 지정. 이미지=루트 파일 시스템+실행 시 설정
  - COPY : 컨텍스트 파일을 이미지로 복사. e.g. COPY index.html /app/
  - RUN : 빌드 과정 셸 명령(패키지 설치). e.g. RUN npm install
  - ENV : 환경 변수 설정. e.g. ENV PORT=8080
  - ENTRYPOINT : 실행 시 명령 지정. CMD랑 같지만 사용자가 다른 명령을 쳐도 무조건 강제 실행. e.g. ENTRYPOINT ["node","server.js"]

**2.3.2 멀티 스테이지 빌드**
- FROM을 여러개 써서 여러 빌드를 하나로. Stage=FROM으로 시작하는 독립 빌드 절차(FROM 이미지 as 이름)
- 멀티 스테이지 : 이미지 경량화. 빌드용+실행용 스테이지 분리. 최종 이미지는 맨 마지막 FROM 기준이라 컴파일 도구 빠져 크기 줄어듦
- COPY --from=스테이지이름 : 지정 스테이지 → 실행 스테이지로 파일 복사
- 빌드킷 : 의존 관계 분석해 최소 스테이지만 실행, 의존 없는 명령은 병렬 실행
- e.g.

  ```
  빌드전 : 내 컴퓨터
  📁 my-project (내 컴퓨터의 현재 폴더)
   ├── 📄 Dockerfile (우리가 작성한 설계도)
   ├── 📁 frontend_code/  (프론트엔드 원본 소스)
   │    ├── 📄 package.json
   │    └── 📁 src/
   └── 📁 backend_code/   (백엔드 원본 소스)
        ├── 📄 Cargo.toml
        └── 📁 src/
  ```

  ```

        └── 📁 target/release/
  ```

  ```
  COPY frontend_code/ .
  RUN npm run build

  [ 1번 주방: frontend ]
  📁 /app/
  ```
