# 2.5 도커 아키텍처와 OCI 런타임

> 🧩 **한 줄 요약** — 도커는 **클라이언트-서버 구조**. `docker` 명령(클라이언트)이 **도커 데몬(dockerd)**에 HTTP API로 요청하고, 데몬은 컨테이너 생명주기를 관리하며 실제 격리 실행은 **OCI 런타임**에 맡긴다.

| 구성 | 역할 |
|---|---|
| **docker CLI**(클라이언트) | 우리가 치는 명령. HTTP API로 데몬에 요청 |
| **도커 데몬**(dockerd, 서버) | 컨테이너 **전체 생명주기**(생성·실행·정지·삭제) 관리 |
| **OCI 런타임** | 격리된 실행 환경을 **컨테이너로 만들거나 조작** |

- 흐름: `docker run …` → (HTTP API) → **dockerd** → **OCI 런타임**이 실제로 격리 환경을 만들어 실행.

> 💡 도커는 지휘(데몬), 실제 컨테이너 생성·조작의 손발은 OCI 런타임. 이 분리 덕에 런타임을 표준(OCI)에 맞춰 교체할 수 있다(→ 4장).
