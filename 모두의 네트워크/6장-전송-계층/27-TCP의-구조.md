# LESSON 27. TCP의 구조

> 📝 **Notion 원본**: https://app.notion.com/p/3c4d7d6851ff81fc872ffcd338d11862

> 🧩 **한 줄 요약** — TCP 헤더는 **포트**(앱 주소) · **일련번호/확인 응답 번호**(순서·수신 확인) · **윈도우 크기**(흐름 제어) · **코드비트**(SYN·ACK·FIN 등 제어 플래그)로 데이터를 정확히 전달한다.

---

## 1. 포트 번호 — 앱의 주소

총 **65,536개**. 세 구간으로 나뉜다.

| 범위 | 종류 | 용도 |
|---|---|---|
| 0-1023 | well-known | 정해진 프로토콜용 (잘 알려진 포트) |
| 1024-49151 | registered | 기관·기업이 사전 등록 |
| 49152-65535 | dynamic | 사용자가 자유롭게 사용 |

- **잘 알려진 포트** : 20 FTP · 22 SSH · 23 Telnet · 25 SMTP · 53 DNS · 80 HTTP · 123 NTP · 443 HTTPS
- 예 : 이메일을 보내면 헤더에 25번 포트가 붙고, 수신자는 그 25번 포트로 이메일 앱에 전달한다.

## 2. 일련번호 · 확인 응답 번호

- **일련번호** : 보내는 데이터가 몇 번째인지 (송신자 → 수신자)
- **확인 응답 번호** : 몇 번째까지 받았는지 (수신자 → 송신자)
- 예 : 1500B를 500B씩 3번 전송 → 순번 `1` / `501` / `1001`

## 3. 윈도우 크기 — 흐름 제어

- 송신자가 **한 번에 보낼 수 있는 최대 크기**.
- 수신자가 받을 수 있는 양을 넘기면 데이터가 유실된다 → 수신자의 윈도우 크기를 **3방향 핸드셰이크**로 확인해 맞춘다.

## 4. 코드비트 (제어 플래그)

`0`=비활성 / `1`=활성.

| 플래그 | 의미 |
|---|---|
| **URG** | 긴급 처리 데이터 있음 |
| **ACK** | 확인 응답 번호 사용 |
| **PSH** | 받은 데이터를 상위 계층에 전달 |
| **RST** | 연결 재설정 |
| **SYN** | 순서 번호 동기화 (연결 시작) |
| **FIN** | 데이터 송신 종료 |

> ⚠️ 원본 노트의 `TURG`·`RSH`는 각각 **URG**·**PSH**의 오타다.

- 전송계층의 헤더 정보
- 포트번호 : 프로그램의 주소
  - 65,536개가 존재
    - 0~1023 : 특정한 쓰임을 위해 사용되는 포트(잘 알려진 포트)
      - 20 : FTP 프로토콜
      - 22 : SSH 프로토콜
      - 23 : Telnet (암호화 아직 안된 텍스트 통신 프로토콜)
      - 25 : SMTP(이메일 전송 프로토콜)
      - 53 : DNS(IP 주소와 도메인 이름 변환 프로토콜)
      - 80 : HTTP(웹페이지 전송 프로토콜)
      - 123 : NTP(시간 동기화 프로토콜)
      - 443 : HTTPS(암호화된 웹페이지 전송 프로토콜)
    - 1024~49151 : 기관/기업들이 사용하는 포트(사전 등록된 포트)
    - 49152~65535 : 일반 사용자가 자유롭게 사용가능한 포트(다이내믹 포트)
    e.g. 송신자가 IP주소로 이메일을 전달하면 헤더에 25번 포트가 생김 / 그러면 수신자는 IP주소 대신 25 포트를 사용해서 이메일을 여는 것
- 일련번호와 확인 응답 번호
  - 일련번호 : 송신자가 수신자에게 보내려는 데이터가 몇 번째인가 알려주는 역할
  - 확인 응답 번호 : 수신자가 몇번째 데이터를 받았는 지 송신자에게 보내는 역할
    - e.g. 보내야할 데이터 크기 : 1500바이트 / 패킷 크기 : 500바이트 라면 총 3번 보낼 텐데 / 1번째 값 : 1+500 / 2번째 값 : 501+500 / 3번째 값 : 1001 + 500
- 윈도우 크기
  - 송신자가 보내는 양보다 수신자가 받을 수 있는 양이 적다면?
    - 튕겨져 나간다
  - 윈도우크기는 송신자가 한 번에 보낼 수 있는 데이터의 최대 크기
    - 수신자가 받을 수 있는 데이터를 확인 후 그걸 고려해서 데이터를 보내겠다
  - 수신자 윈도우 크기는 3방향 핸드셰이크로 확인
- 코드비트
  - 0 : 비활성화
  - 1 : 활성화
    - 항목
      - TURG : 긴급 처리 데이터 있음
      - ACK : 확인 응답 번호 사용
      - RSH : TCP가 받은 데이터를 상위 계층에 전달
      - RST : 연결 재설정
      - SYN : 연결을 초기화하기 위해 순서 번호 동기화
      - FIN : 데이터 송신 종료
