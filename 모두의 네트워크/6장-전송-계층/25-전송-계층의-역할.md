# LESSON 25. 전송 계층의 역할

> 📝 **Notion 원본**: https://app.notion.com/p/3c4d7d6851ff81969726d4fc69c036c9

> 🧩 **한 줄 요약** — 전송 계층은 데이터를 **오류 없이** 올바른 앱(**포트**)에 전달한다. 오류 점검은 **혼잡 제어**(네트워크 상황) · **흐름 제어**(수신자 속도) · **오류 제어**(재전송)로 나뉜다.

---

## 1. 전송 계층의 두 역할

- **오류 점검** : 데이터가 제대로 전달됐는지 확인·보정
- **앱 식별** : 받은 데이터를 어느 앱(**포트**)에 넘길지 구분

## 2. 오류 점검 3가지

| 방식 | 무엇을 조절 | 방법 |
|---|---|---|
| **혼잡 제어** | 네트워크 전체의 혼잡 | ACK 오면 전송량 2배씩↑(슬로 스타트), 타임아웃·중복 ACK면↓ |
| **흐름 제어** | 수신자가 감당할 양 | 정지-대기 : ACK를 받아야 다음 데이터 전송 |
| **오류 제어** | 데이터 정확성 | 확인 응답·시간 초과로 오류 감지 → 재전송 |

> 💡 혼잡 제어는 **네트워크 전체** 상황을, 흐름 제어는 **수신자 한 명**의 처리 속도를 본다.

## 3. 재전송이 필요한 상황

- 데이터가 **손실**됐을 때 · **순서가 바뀌**었을 때 · **훼손**됐을 때

---

3. 슬로 스타트에서 전송량은 어떻게 변하나?

<details>
<summary>📄 원본 노트 (정리 전 원문)</summary>

- 전송계층 : 오류점검 + 데이터를 제대로 받았을 때 어떤 APP으로 전달해야하는 지 식별하는 기능
  - 오류를 점검하는 방법
    - 혼잡제어
      - 네트워크로 가는 정보량을 조절해서 네트워크가 혼잡해지지 않도록 하는 방법
        - 송신자 : 하나의 데이터 전송
        - 수신자 : 정상 전송되면 ACK를 받으면 전송량을 2배씩 늘려나가는 것
        - 그러다 타임 아웃 or 같은 ACK를 여러번 받으면 데이터를 줄여서 보냄
    - 흐름제어
      - 정지-대기방식
        - 송신자 : 데이터 전송
        - 수신자
          - 정상 전송 : 송신자에게 ACK 전송
          - 프래임 손실(데이터 못받음) : 송신자가 다시 보냄
          - 수신자 쪽 인증 ACK 가 유실 되었을 때 : 송신자의 중복 데이터는 무시하고 ACK만 다시 전송
        - 즉, 송신자 쪽에서 수신자의 ACK를 받으면 다음 데이터를 보내는 방법
    - 오류제어
      - 확인 응답 : 송신자가 수신자에게 ACK를 못받으면 오류로 판단
      - 시간초과 : 특정시간 내 ACK가 없으면 세그먼트에 오류가 있다 판단
    - 재전송하는 상황
      - 데이터가 중간에 손실 될 때
      - 데이터 순서가 바뀌었을 때
      - 데이터가 훼손 되었을 때

</details>
