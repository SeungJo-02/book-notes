# LESSON 39. 무선 랜의 구성 방식

> 📝 **Notion 원본**: https://app.notion.com/p/3c4d7d6851ff8123ae82e2da1a25df3a

> 🧩 **한 줄 요약** — 무선 랜을 구성하는 방식은 둘. **액세스 포인트를 중심에 두느냐(인프라스트럭처)**, **장치끼리 직접 붙느냐(애드혹)**. 우리가 쓰는 Wi-Fi는 전부 앞쪽이다.

---

## 1. 인프라스트럭처 모드

- 무선 랜에 연결된 **모든 장치가 액세스 포인트에 연결** 되는 방식
  - 액세스 포인트가 장치 간 통신을 **중계**
  - 장치끼리 데이터를 주고받을 때도 **반드시 AP를 거침** (직접 통신하지 않음)
- 장점
  - AP가 유선과 이어져 있어 **인터넷 연결이 가능**
  - 중앙에서 관리 → 인증·보안·접속 제어를 한곳에서
  - 장치가 늘어나도 구조가 단순 (AP만 보면 됨)
- 집·회사·카페의 Wi-Fi가 전부 이 방식

<details>
<summary>💡 BSS와 ESS — AP를 여러 대 놓을 때</summary>

- **BSS** (Basic Service Set) : AP **한 대** 가 커버하는 영역
- **ESS** (Extended Service Set) : **여러 AP를 같은 SSID로 묶어** 넓은 공간을 덮은 것
- **로밍** : 사용자가 이동하면 신호가 더 강한 AP로 **끊김 없이 넘어감**
  - 회사나 대학 건물에서 걸어다녀도 Wi-Fi가 안 끊기는 이유가 이것

</details>

## 2. 애드혹 모드

- **액세스 포인트 없이** 장치끼리 **직접 연결** 하는 방식
  - 중계자가 없으므로 서로가 서로에게 직접 전파를 보냄
- 특징
  - 별도 장비가 필요 없어 **즉석에서 구성 가능**
  - 보통 **작은 범위·소수의 기기** 에서 사용
  - 인터넷 연결은 기본적으로 안 됨 (누군가 유선에 물려 있지 않는 한)
  - 기기가 늘수록 연결 수가 급증해 **확장성이 나쁨**
- 현대적 사례 : **Wi-Fi Direct** (기기 간 파일 전송), 일부 게임기 근거리 대전

## 3. 비교

| 기준 | 인프라스트럭처 | 애드혹 |
|---|---|---|
| 중심 장비 | **액세스 포인트 필요** | 없음 |
| 통신 경로 | 장치 → AP → 장치 | 장치 ↔ 장치 (직접) |
| 인터넷 연결 | ⭕ (AP가 유선과 연결) | ✕ (기본적으로 불가) |
| 관리·보안 | 중앙 집중 → 용이 | 분산 → 어려움 |
| 확장성 | 좋음 (AP 추가) | 나쁨 (연결 수 급증) |
| 용도 | 집·회사·카페 Wi-Fi | 기기 간 임시 직접 전송 |

---

## 4. 정리

| 개념 | 한 줄 정의 |
|---|---|
| 인프라스트럭처 | 모든 통신이 AP를 거치는 방식 — 일반적인 Wi-Fi |
| 애드혹 | AP 없이 장치끼리 직접 연결 |
| BSS / ESS | AP 1대의 영역 / 여러 AP를 묶은 영역 |
| 로밍 | 이동 시 더 강한 AP로 끊김 없이 전환 |

---

## 🔁 셀프 체크

1. 인프라스트럭처 모드에서 같은 방의 두 노트북이 파일을 주고받으면, 데이터는 어디를 거치는가?
2. 애드혹으로는 왜 보통 인터넷을 못 쓰는가?
3. 건물 안을 걸어다녀도 Wi-Fi가 안 끊기는 이유는?

<details>
<summary>답</summary>

1. 바로 옆에 있어도 **반드시 액세스 포인트를 거친다.** 인프라스트럭처 모드에서는 AP가 모든 통신을 중계한다.
2. 애드혹에는 **유선과 이어주는 장치(AP)가 없기 때문** 이다. 인터넷에 나가려면 누군가 유선에 물려 있어야 한다.
3. **ESS** 로 여러 AP를 같은 SSID로 묶어두고, 이동하면 신호가 더 강한 AP로 **로밍** 되기 때문이다.

</details>

    - 모든 장치가 액세스 포인트를 거침

- 애드혹
  - 액세스 포인트없이 장치간 직접 연결
    - 작은 범위 내에서 보통 사용

</details>
