# LESSON 30. 응용 계층의 역할

> 📝 **Notion 원본**: https://app.notion.com/p/3c4d7d6851ff817aa138da651c2bf875

> 🧩 **한 줄 요약** — 응용 계층은 사람이 쓰는 앱과 네트워크를 잇는 **맨 위 계층**이고, 여기서 정하는 건 결국 하나다: **"어떤 프로토콜을, 몇 번 포트로 쓸 것인가."**

---

## 1. 클라이언트-서버 모델

- **클라이언트** — 요청하는 쪽 (브라우저, 메일 앱)
- **서버** — 요청받아 제공하는 쪽 (웹 서버, 메일 서버)
- 한쪽이 요청하고 다른 쪽이 응답하는 이 구조를 **클라이언트-서버 모델**이라고 부른다.

> 💡 **대비되는 구조 — P2P** : 모든 참여자가 클라이언트이면서 동시에 서버. 토렌트·블록체인이 이 방식이다. "요청하는 쪽과 주는 쪽이 고정인가"가 두 모델을 가르는 기준.

## 2. 프로토콜은 "규격"이다

- 프로토콜 = **이 순서로, 이 형식으로 주고받자는 약속**.
- 약속이 같기 때문에 서로 다른 회사가 만든 브라우저와 서버가 문제없이 통신한다.
- 응용 계층 프로토콜은 대부분 **포트 번호가 관례로 정해져** 있어서, 포트만 봐도 무슨 통신인지 짐작할 수 있다.

## 3. 자주 쓰는 프로토콜과 포트

| 프로토콜 | 포트 | 용도 |
|---|---|---|
| HTTP | 80 | 웹 |
| HTTPS | 443 | 암호화된 웹 (현재 사실상 표준) |
| DNS | 53 | 도메인 → IP 변환 |
| SMTP | 25 | 메일 **발신** |
| POP3 / IMAP | 110 / 143 | 메일 **수신** |
| FTP | 21 / 20 | 파일 전송 (21=제어, 20=데이터) |
| SSH | 22 | 원격 접속 |

> 📌 **포트는 원래 전송 계층의 개념**이다. 응용 계층 프로토콜이 포트를 "가지고 있는" 게 아니라, **관례로 배정된 번호**를 쓰는 것뿐이다. 0~1023번을 **잘 알려진 포트(Well-known port)** 라 하고, 이 범위는 함부로 다른 용도로 쓰지 않는다.

<details>
<summary>⚠️ FTP가 포트를 2개 쓰는 이유 — 그리고 20번을 안 쓰는 경우</summary>

- FTP는 **명령을 주고받는 연결(21)** 과 **파일이 실제로 흐르는 연결(20)** 을 분리한다. 파일을 받는 도중에도 "취소" 같은 명령을 보낼 수 있는 이유가 이것.
- 다만 20번은 **액티브 모드**에서만 쓴다. 서버가 클라이언트 쪽으로 연결을 거는 방식이라 방화벽·NAT에 자주 막힌다.
- 그래서 실무에서는 클라이언트가 양쪽 연결을 모두 거는 **패시브 모드**를 주로 쓰고, 이때 데이터 포트는 20번이 아니라 서버가 지정한 임의의 높은 포트가 된다.

</details>

## 4. 정리

| 개념 | 한 줄 정의 |
|---|---|
| 응용 계층 | 앱과 네트워크가 만나는 최상위 계층 |
| 클라이언트-서버 | 요청하는 쪽과 제공하는 쪽이 고정된 구조 |
| 프로토콜 | 주고받는 순서와 형식에 대한 약속 |
| 잘 알려진 포트 | 0~1023, 주요 프로토콜에 관례로 배정된 번호 |

## 🔁 셀프 체크

1. 프로토콜이 없으면 구체적으로 무엇이 안 되는가?
2. 메일을 "보낼 때"와 "받을 때" 프로토콜이 나뉘어 있는 이유는?
3. FTP는 왜 포트를 2개 쓰는가?

<details>
<summary>답</summary>

1. 데이터가 도착해도 **어디까지가 헤더고 어디부터가 본문인지, 어떤 순서로 응답해야 하는지** 를 알 수 없다. 형식과 순서의 약속이 곧 프로토콜이다.
2. 발신은 **내 서버로 밀어 넣는 일(SMTP)**, 수신은 **내 서버에서 꺼내 오는 일(POP3/IMAP)** 로 방향과 주체가 다르기 때문.
3. **명령용 연결(21)과 데이터용 연결(20)을 분리** 해, 파일 전송 중에도 명령을 주고받을 수 있게 하려고.

</details>
